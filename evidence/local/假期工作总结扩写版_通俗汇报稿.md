# 假期工作总结

这段时间的工作主要围绕一个问题展开：在多智能体系统生成报告的过程中，最终的一段话到底来自哪些上游材料？现有系统通常能记录哪个 Agent 调用了哪个 Agent，却很难继续细化到文本片段。比如 Researcher 检索了十几段资料，最后交给 Reporter 一段总结，我们希望进一步判断，这段总结主要使用了其中哪几段资料。这就是 MemoryFlow 想解决的 Chunk 级信息来源恢复问题。这里的 Chunk 可以理解为一段相对完整的文本，比如一条检索结果、一段 Researcher 总结，或者最终报告中的一个段落。

要研究这个问题，第一步是先有一个可控、能准确评价的方法测试环境。我们最开始使用 LongCite 数据做引用来源恢复，因为其中的目标句子带有引用信息，可以把被引用的原文当作正确来源。但原有数据协议不够干净，候选数量和正例数量也不完全统一，实验之间不容易直接比较。因此，假期里先从固定版本的 LongCite-45k 官方原始数据重新构造了 LC-Sent-15 数据集。

LC-Sent-15 是一个“15 选 1”任务。每个样本包含一个需要寻找来源的目标句子，以及来自同一篇文档的 15 个候选原句，其中只有 1 个是正确来源。之所以选择同一篇文档内的候选，是因为这些句子往往主题接近，比从完全无关的文章中随机抽负例更有难度，也更接近真实引用核查。固定为 15 个候选、1 个正例后，不同方法面对的是同一项任务，结果也更容易解释。

数据被分成三部分：训练集用于学习关系评分器，验证集用于比较方法和确定方案，Reserve 集保留到方法完全固定后再做独立确认。训练集有 854 个 Target，共 12,810 个 Target-Source 文本对；验证集有 228 个 Target，共 3,420 对；Reserve 有 218 个 Target，共 3,270 对。这里的 Target 是需要寻找来源的句子，Source 是候选来源句子。数据划分按文档隔离，同一篇文档不会同时进入训练集和验证集，这样可以避免模型因为见过相同文档而得到虚高结果。

完成数据重构后，我们先重新检查原来的 Anchor + Attention 方法。Anchor 可以理解为程序放在每个文本 Chunk 末尾的一个特殊记号。模型读完整段文字后，这个位置会形成一个向量，我们原本希望它能像“段落摘要”一样汇聚整段内容。Attention 是 Transformer 内部计算不同位置之间关联程度的权重。旧方法的想法是，让 Target 的 Anchor 去关注各个 Source 的 Anchor，再把 Attention 权重作为来源分数。

这套设计有两个吸引人的地方。第一，每个 Chunk 都可以用统一的 Anchor 表示，方便把整次 Agent 运行组织成一张图。第二，多个候选 Source 可以一起放进一次模型前向计算，比逐对调用模型更省时间。但它也有一个很强的前提：Anchor 必须真的能够概括整段文字，而且 Attention 权重必须能够表示“这段结论来自哪段材料”。这两个前提不能只靠直觉，需要实验验证。

为了排除“原来模型太小，所以效果不好”这个可能，我们换用 Qwen2.5-7B 重跑了 Anchor + Attention。7B 表示模型大约有 70 亿参数，比早期使用的 1.5B 模型容量更大。结果如下：

| 指标 | 数值 |
|---|---:|
| nDCG@5 | 0.581699 |
| MRR | 0.576958 |
| AUPRC | 0.335071 |

这三个指标分别观察不同问题。nDCG@5 只看前五名，正确来源排得越靠前，得分越高，同时它也会考虑多个相关结果的排序质量，满分为 1。MRR 关注第一个正确来源排在第几名。如果正确来源排第一，该样本得 1 分；排第二得 0.5 分；排第三得约 0.33 分，然后对所有样本取平均。AUPRC 则不只看组内排名，而是把每个 Target-Source 文本对当成“有关”或“无关”来判断，综合观察模型在不同阈值下的准确率和召回率。这个指标特别适合正例少、负例多的情况，同样是越高越好。

从结果看，7B Anchor 不是完全没有学到信息，但表现仍然一般。正确来源能够被排到相对靠前的位置，却还不能稳定排在最前面；如果把每个候选对当成一条边来判断，正负样本的区分也不够清楚。换用更大的 Qwen 后问题没有自然消失，说明主要瓶颈不是模型参数量，而是 Anchor 如何概括文本，以及 Attention 能不能直接承担关系判断。

基于这个判断，我们把“文本表示”和“关系判断”拆开处理。Qwen 仍然负责阅读文本，但不再直接把某个 Attention 数值当作最后答案。具体做法是，先用冻结的 Qwen2.5-7B 把每个 Target 和 Source 编码成一个全文向量。所谓冻结，是指 Qwen 的参数不再训练，只把它当作固定的文本编码器。然后引入 MLP，根据两个文本向量之间的关系输出来源分数。

MLP 的全称是多层感知机，可以把它理解为一个很小的可训练打分网络。它接收 Target 和 Source 的向量，以及两者的相同和差异，再学习什么样的组合更像真实引用关系。这样做的原因很直接：Qwen 的通用表示可能已经包含语义信息，但“语义相近”不等于“存在来源关系”，需要一个专门针对当前任务训练的判断器。

实验中先放了两个容易理解的参照。BM25 是传统关键词匹配方法，主要看两段文本是否共享相同词语。Qwen 余弦不训练关系模型，只计算两个全文向量的夹角，夹角越小说明整体语义越接近。

在这两个参照之上，我们训练了 R-SYM 和 D-Full-64。R-SYM 把两个向量的逐维乘积、绝对差和余弦相似度交给 MLP。它擅长学习两段文本是否匹配，但交换 Target 和 Source 后，输入特征不会变化，所以称为“对称关系模型”。D-Full-64 则分别保留 Target 和 Source 的原始向量，再加入乘积、差值和余弦特征，模型由此能够区分谁是 Target、谁是 Source。名称中的 64 指的是 MLP 中间层有 64 个神经元，只是这个小型打分网络的宽度设置。

在 228 个验证集 Target 上，结果如下：

| 方法 | Hit@1 | MRR | nDCG@5 |
|---|---:|---:|---:|
| BM25 | 68.42% | 0.7470 | 0.7433 |
| Qwen 余弦 | 45.18% | 0.5954 | 0.6199 |
| R-SYM | 75.44% | 0.8273 | 0.8436 |
| D-Full-64 | 78.07% | 0.8514 | 0.8700 |
| D-Full-64 + BM25 | 83.19% | 0.8857 | 0.8971 |

Hit@1 是最直观的指标：看模型排在第一名的候选是不是正确来源。比如 Hit@1 为 68.42%，可以理解为平均每 100 个 Target，大约有 68 个能一次找对。MRR 比 Hit@1 更细一些，即使没有排第一，只要正确来源还在第二、第三名，也会得到部分分数。nDCG@5 则观察前五名的整体排序情况。所以汇报时可以先用 Hit@1 讲清楚“第一名找对了多少”，再用 MRR 和 nDCG@5 说明其余候选的排序是否合理。

这组结果的变化很直观。BM25 达到 68.42%，LongCite 中显然存在较强的词面线索，目标句和来源句经常共享关键词。单独使用 Qwen 余弦只有 45.18%。原因也不难理解：有些句子讨论的是同一主题，向量很接近，但它们之间未必存在引用关系。通用语义相似度还少了一步专门的关系判断。

加入关系训练后，R-SYM 提升到 75.44%。Qwen 向量里其实已经有可用信息，缺的是一个会判断 Target 和 Source 具体关系的模型。D-Full-64 进一步达到 78.07%。它把 Target 和 Source 分开输入，保留两者的角色，比完全对称的匹配方式更适合处理带方向的来源判断。

目前最好的结果来自 D-Full-64 与 BM25 的结合，Hit@1 达到 83.19%。这个方法把 D-Full-64 的语义关系分数与 BM25 的关键词分数融合起来。融合权重不是在验证集上反复试出来的，而是先在训练集内部做交叉验证，固定为 65% 的神经模型分数加 35% 的 BM25 分数，再到验证集做一次评估。

两种方法各有所长。BM25 对词语、数字和实体重合非常敏感，D-Full-64 更能处理摘要、改写和语义对应。它们放在一起，刚好能补掉一部分彼此容易漏掉的样本。

数字从 68% 提高到 83% 是最直观的结果，背后更重要的是实验路径。我们先重构了可复现的 15 选 1 数据任务，再用 7B 实验排除了“模型太小”这个解释，随后把文本编码与关系判断拆开，让 MLP 专门学习 Target 和 Source 的关系。到这里已经比较明确：单独依赖 Attention 或通用文本相似度都不够，关系需要专门学习；词面信号和语义信号又能互相补充。

不过 LongCite 仍然是引用来源恢复的代理任务，不是真实的多 Agent 运行。它能回答“哪段原文最可能支持这句话”，但还不能完整回答“某个 Researcher 在这一次运行中实际读了什么，以及 Reporter 最后用了哪段 Summary”。因此下一阶段会把方法放到真实 Agent 轨迹中验证。计划使用稳定版本的 Stack-Planner 运行查询，记录检索得到的 Source、Researcher 生成的 Summary，以及 Reporter 的最终输出。第一步只跑一个 Query，把数据格式和 Source 到 Summary 的对应关系记录完整；确认可以评价后，再运行剩余 Query，并比较 BM25、Qwen 余弦、R-SYM、D-Full-64 和融合方法。

真实 Agent 场景的环境配置和结构化轨迹采集目前还在准备。等第一条完整轨迹拿到后，再看这些在 LongCite 上有效的方法，面对真正经历过检索、摘要和改写的信息时还能剩下多少能力。
