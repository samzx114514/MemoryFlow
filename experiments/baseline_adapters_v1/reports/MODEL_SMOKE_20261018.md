## 固定配置与适配边界

CLM 使用固定 Qwen3-8B 权重、作者发布投影头及 Engine。编码由现有 Transformers AutoModel 执行，bf16、SDPA、单条无 padding 输入、末 token 表示、L2 归一化；没有另外安装 vLLM，也没有测量与 vLLM 的数值等价性。输入仍是整段 Researcher Summary，不是原子 Claim。候选 softmax 是候选集合内的相对分数，不是正确概率。

艺峰使用本地 Qwen2.5-7B-Instruct 和论文表的零基头 (19,15)，greedy 生成，作者默认引用阈值 -0.7、relative cutoff 0.5。用户已确认不重新选头。师兄给出的原始 JSON 有 784 个头，每头 44 个分数；求和第一为 (14,0)，(19,15) 排第五，保留这一差异。原始 JSON 只放忽略目录与服务器任务目录，不提交 Git。

艺峰按原问题和检索片段重新生成回答，不解释 SP1 原回答的内部注意力。来源句子通过字符范围映射回原 chunk；跨 chunk 的句子保留全部重叠 ID，不擅自选一个。

## 首轮检查发现

CLM 在 Python 样例中把一段讨论教程设计的材料排在首位，softmax 为 0.785334；包含教程核心介绍的片段排第二。CUAD 样例中，CLM 首位是授权/责任相关片段（0.922523），原 Researcher 引用的第 2.1 条所在片段排第九。尚无语义 Gold，不能据此计算准确率；高相对分数也不能当成来源正确的证据。

艺峰在 Python 样例中生成了简短介绍并给出句子级引用。CUAD 样例输出 no_answer，与原 SP1 的 found 不同；方法还给过渡语和 no_answer 标记添加了引用。它说明管线确实运行了，但生成判断与引用有效性仍需检查，不能称为论文效果复现成功。

下一轮宜先固定少量原子目标和可人工核查的来源关系，并明确标记非事实输出（网址、过渡语、状态标记），再比较各方法。保留本轮原始结果，不按这两例调头、阈值或提示词。
