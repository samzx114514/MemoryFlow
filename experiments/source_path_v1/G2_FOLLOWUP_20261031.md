# G2 后续：递归查询、森林修正与最后输入统计

日期：2026-10-31。本轮只做 CPU 读取与布局/解析，不调用模型、不重跑 case。

## 结果

三项旧缺口已修：

1. `query.py` 不再跳过 `estimate` 边；路径防环改为 branch-local，因此同一目标经“摘要”和“直达原文”的两条合法路径都会保留。
2. `build_forest.py` 不再用整篇 system prompt 搜索 `CentralAgent`。旧规则把提示尾部提到 `CentralAgent` 的子 Agent 全判成 central；改为只看首行角色声明。
3. `compare_views.py` 的“最后调用可见”同时统计 `history` 边和 `input_occurrences`，不再只数原文、漏掉摘要。

真实 CUAD 查询结果：

```text
report_span_0
  记录生成 → call7（报告者）
  记录历史 → 原文 2593:3850
  回放估计 0.6437 → summary_final
    summary 生成 → call4（研究者）/ 另一生成记录
    summary → 13 个上游原文片段，其中 2593:3850 为 0.7569
  回放估计 0.3563 → 原文 2593:3850
```

最后调用实际可见：

```text
last-call-only sees: 2 units
  summary_final
  原文 2593:3850
```

这更正了“最后一步只看见 1 个单元”的旧统计；不再把摘要漏记解释成最后调用看不见。

## 森林

修正后的 v6：

```text
calls: 44
roots: 20 = central 14 + coder 3 + perception 2 + memory_recaller 1
branches under recovered prefix: 0
```

旧 `forest_v6.json` 的 44 calls 全部 central，是角色分类 bug，不是真实所有调用都在 Central。修正后子 Agent 已有各自 roots；delegate→子 Agent 的 session/委派映射仍未落盘，标为 unresolved。

注意：`branches=0` 只表示在“同角色 + 完整消息身份 + 时间顺序约束”下没有恢复出分支，不能证明真实系统没有分支。
