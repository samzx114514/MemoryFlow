# MemoryFlow 研究背景与阶段结论

**整理日期：2026-10-14。** 本文给新读者一个可独立阅读的入口。数字来自仓库内的指标和报告，具体对应见 [结果表](RESULTS.md) 与 [实验索引](EXPERIMENT_INDEX.md)。LongCite 的引用标签是 Silver（自动提取的近似标注），不是人工确证的真实 Agent 信息流。

## 1. 最初的问题

设想 Researcher 检索了几篇材料，写出“方法甲在某任务上优于方法乙”的一段 Memory Summary；Reporter 又把这句话放进最终报告。我们想追问：总结里的这句话是由哪一段检索材料支持的？Reporter 在这一次运行里实际看到了哪段总结？如果拿掉某段材料，结论会不会改变？普通 Agent 日志往往只能显示哪个步骤调用了哪个步骤，难以回答到文本片段（Chunk）的粒度。

这三个问题是不同层次：**语义支持**是材料能否支持结论，**实际使用**是本次运行是否读取或引用了材料，**因果影响**是替换材料会不会改变结论。已有 LongCite 实验主要研究第一层；当前不能把高检索分数直接称为真实信息流恢复。

## 2. 从 Anchor + Attention 起步

最初把每个 Chunk 后面由程序插入一个共享的 **Anchor**，希望模型在该位置形成整段文字的压缩表示。把 Target（待找来源的句子）和多个 Source（候选来源）一起送入模型，靠结构化 Attention mask 允许特定 Chunk 交互，再读取 Target Anchor 对 Source Anchor 的注意力，给候选来源排序。**Packed 推理**意味着多候选共用一次模型前向，而非每对单独前向。它在工程上可运行并节省推理成本，但 packed 与逐对评分的排序并不完全等价。

在旧 c8 协议中，最佳 7B Anchor C4 的 Dev MRR 为 0.576958、nDCG@5 为 0.581699、Edge AUPRC 为 0.335071。它显示有一定来源信号，却不足以把 Attention 当成可靠的语义边。扩大模型并没有消除 Anchor 压缩和 Attention 读出的问题，因此停止把继续扩模当作主线。这里的 Anchor 是可训练向量，训练不是语言模型 SFT，模型也不会自己生成 Anchor 位置。

## 3. 冻结表示，再学习两段文字的关系

下一步把 Qwen2.5-7B 固定为编码器，用整段文本的平均隐藏表示 `F_mean` 生成 Target 和 Source 向量，再用轻量多层感知机（MLP）学习两者是否构成来源关系。Qwen 不参与评分头的训练。只用向量余弦距离仍不够，因为“讨论同一主题”未必等于“这句话来自那句话”。

**R-SYM** 是对称关系评分器：输入两向量的逐维乘积、绝对差和余弦相似度，交换 Target/Source 时分数不变。旧 c8 的分组、置乱和困难子集实验支持它确实使用了 Target–Source 配对信息，优于只记 Source 先验；但它无法证明方向。旧 c8 的 Ranking 和 Edge 使用**不同训练 checkpoint**，不能把两个指标写成一个模型的一次测量。

**D-Full-64** 是保留 Target、Source 各自向量及交互特征的角色感知评分器，隐藏层宽度为 64。它能表达方向，但在 LC-Sent-15 上更高的点估计尚不足以证明方向性是改进原因；Train–Dev 差距也更大。**固定 Fusion** 将 D-Full-64 与传统关键词检索 BM25 的分数混合：权重在 Train 的五折 OOF（折外预测）上定为 0.65/0.35，再一次性评估 Dev。它是强系统组合，而非独立新方法的证明。

## 4. LC-Sent-15 的构造和结果

为避免旧协议候选数与正例数不统一，本机数据准备代码从固定修订版的 LongCite-45k 重建了 **LC-Sent-15**：每个 Target 在同一文档内有 15 个 Source 候选，严格一个正例，按文档隔离 Train/Dev，Reserve 封存。Train 854 Targets / 12,810 pairs；Dev 228 / 3,420；Reserve 218 / 3,270。Reserve 未用于本表的选择。部分负例只是标点或排版碎片，这是协议的已知限制。

在 Dev 上，BM25、Qwen 余弦、R-SYM、D-Full-64、固定 Fusion 的 Hit@1 依次为 0.6842、0.451754、0.754386、0.780702、0.831871。Hit@1 是第一名正确的 Target 比例，15 选 1 随机基线约 6.67%；MRR 还奖励正确来源排在第二、第三的情形；nDCG@5 衡量前五名排序。R-SYM、D-Full 的数字是多随机种子均值。Fusion 的优势支持词法和学习的关系分数互补；中文子集仍明显难于英文。具体完整指标与报告链接在 [RESULTS](RESULTS.md)。

## 5. 向报告生成转移

**Synthetic Summary Track A** 从单份文档生成 Summary，正例由生成过程给出，共 137 个唯一 Target；BM25 Hit@1 已到 0.9416，说明任务过于有利于词面匹配。**Track B** 有 10 个多文档 Summary、143 个子句和 4,194 个候选来源句，但没有 Gold 或 Judge 结果；方法一致率只是诊断，绝不是准确率。两者都只是 smoke test，不宜继续以其分数当主要科学结论。

已有本机旧 SP 日志可以提取工作流和文本 Chunk，但 20 个 pilot Case 中没有可直接恢复的 Source→Report 语义 Gold 边。后续选定较稳定的 SP1.0 轨迹生成分支，目标是自然运行查询、保留检索 Source、Researcher Summary、Reporter 输出及稳定 ID。按目前找到的产物，**没有可用于本研究主协议的完整真实 SP1 轨迹和 Source-to-Summary 分数**。这也是从 LongCite 代理任务转向真实 Agent 轨迹的关键缺口。

艺峰方法是一条独立的、生成时使用 Attention 做引用归因的对比线。现有对比报告没有 LC-Sent-15 的可比评分协议，也缺固定选出的引用 head；Head probing 目录的 readiness 报告显示 200 样本 probe 未完成。它目前不能与上述 Dev 表并列。

## 6. 现阶段可以说什么

已经建立可复现的 15 候选引用来源代理任务；Anchor packed 设计工程可行，但 Attention 不能直接当可靠信息流边；冻结 Qwen 表示加非线性关系评分能更好地做语义来源匹配；固定词法融合在 LC-Sent-15 Dev 上更强。仍未解决的是：真正运行中的可见性与使用证据、方向性与因果性、跨域泛化、真实多 Agent 标注和对比方法的统一协议。用户将重新考虑研究方向，下一阶段路线应依据这些证据讨论，而非自动沿用旧执行计划。
