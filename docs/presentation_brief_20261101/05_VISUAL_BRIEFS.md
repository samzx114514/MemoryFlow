## F1：方法二森林，先让老师看懂结构

至少画主会话和子会话两棵树。主树：初始上下文 H0，调用后 H1，后续 H2；从 H1 增加另一后续 H2' 表示共享历史后的分歧。子树：独立输入 S0，经分析得到 S1。主/子关系另外画委派与摘要返回。

这幅是概念示意，不需要把真实 v6 的 14/3/2/1 恢复链数量塞进去。节点解释为可观测上下文；树组织可见历史，调用标在相应路径上。工具/文件操作并非都属于 LLM 调用，应另标必要的内容传递。

用逐层出现或三幅小图：连续历史；共享前缀后分歧；不同会话各有一棵树。这样解释为什么是树、为什么是森林，比角色名称方框有效。

## F2：在调用旁挂局部矩阵，再反向追查

从 F1 放大一个调用：输入片段 a/b/c，输出片段 x/y，矩阵每格表示局部关联。在概念图中不填实测数值。再用一条返回的摘要连接子会话与主会话，最后从最终句反向高亮到摘要和原文。

记录确认用蓝色实线，回放估计用橙色虚线，缺口用灰色断点。传递箭头方向与查询方向分别说明，不能混为一套没有图例的箭头。

避免把 Agent 画成嵌入向量网络；不画 RL reward、梯度或训练损失。概念图只解释我们要构建和查询什么。

## F3：正式案例版面

四列或两层：原始任务/规则，关键解释，中间摘要/前版报告，最终判断。用真实短原句与颜色对应；旁边小字标生成调用/版本，详细 ID 进入讲稿。

当前只有经过记录确认的关系画实线，尚未核准的局部分数与上游映射写待补。页面仍应包含具体内容与核查问题，不留一个空的“case study”框。

原文同时直达最终调用时保留该路径；没有支撑段落时保留断点，不为好看补一条关系。

## F4：方法一与数据图

前缀复用图使用同色长前缀与不同目标块；优化后只保留一份前缀，组内目标依次分析。不要把现有 D 画成多个分支一次前向。

packing 另用虚线框写“探索中”，其 mask 图可说明分支应彼此隔离，但不能在结果栏放失败探针的速度。

质量图主表与柱图不必全部重复：一处突出完整组 @10，另一处保留 @5/Frag@1 的取舍。N=47 放在图中，不写 accuracy。

## F5：真实任务时间线

E0 是执行任务；E1 在同一保存轨迹后追加分析；E2 是真实执行与分析重叠。三条行中分别标答案时刻、来源齐备时刻、待处理积压和 GPU 配置。

没有 E2 数据时，条形长度必须标“结构示意，非比例”；时间字段写待测。完整任务额外等待应由实际两个事件计算，不能用局部 forward 时间外推。
