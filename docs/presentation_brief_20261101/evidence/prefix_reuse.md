# 效率补充：整批前缀复用 B/D（2026-10-29）

## 协议

- 输入：`genmem_quality_v2` 冻结的 88 个可容纳目标（无目标前文版本），同一 `model_input.jsonl`、同一提示词、候选、顺序与 dtype；
  固定头 (19,15)、Qwen2.5-7B-Instruct、bf16、eager、`prefill_chunk=2048`。
- B：每个目标各自重算前缀，目标逐个处理；
- D：相同 tokenized 前缀（`prompt_ids[:-1]`）分组，组内一次前缀、各目标依次跑自己的 block；
- 只有 tokenized 前缀完全相同且位置/mask 设置一致时才复用；分数用同一冻结排序规则比较。

## 主结果（同一 GPU、同一软件版本，交替顺序，正式最多三遍）

| 遍 | B 总时长 | D 总时长 | 加速比 | B 前缀/分支 | D 前缀/分支 | 峰值 allocated / reserved |
|---:|---:|---:|---:|---|---|---|
| 1 | 536.87 s | 140.72 s | 3.82× | 523.58 / 7.14 s | 134.21 / 5.00 s | 32.82 / 33.08 GiB |
| 2 | 405.40 s | 140.94 s | 2.88× | 394.14 / 5.00 s | 133.52 / 5.00 s | 32.82 / 33.08 GiB |
| 3 | 406.09 s | 140.61 s | 2.89× | 393.59 / 4.99 s | 133.08 / 5.00 s | 32.82 / 33.08 GiB |
| **中位** | **406.1 s** | **140.7 s** | **2.89×** | | | |

- 第 1 遍的 B 明显偏慢（536.9 s），D 三遍非常稳定（140.6–140.9 s）→ **以中位与范围报告，不把第 1 遍当异常删掉**。
- 峰值显存 B/D 相同（32.82 GiB allocated，33.08 GiB reserved），说明 D 的分组复用没有额外占用。

## 一致性

三遍都逐目标比较 B 与 D 的候选分数（归一化到候选和为 1）：

| 遍 | 最大绝对差 | 平均绝对差 | Top-1 一致 | Top-5 一致 |
|---:|---:|---:|---:|---:|
| 1 | 0.0 | 0.0 | 88/88 | 88/88 |
| 2 | 0.0 | 0.0 | 88/88 | 88/88 |
| 3 | 0.0 | 0.0 | 88/88 | 88/88 |

**逐候选分数完全相同**，不是“排序近似”。原因是 D 复用的是完全相同的 tokenized 前缀，且 `crop_cache` 回到同一前缀长度后再跑分支。

## 怎么读这个数

- 之前的 **6.7–7.6×** 来自三个组内共享前缀的（小）实验，原样保留；本轮是**整批 88 目标**，可复用比例 64.3%，
  剩下的 35.7% 前缀（24 个单目标组）无论如何都要各算一次，所以整批加速比落在 **2.89×** 量级是合理的，不与组内数字相乘或相加。
- 与 PPT 的生成时溯源数字（第 3–4 页）回答的是不同问题：这里是**已有文本的独立回放**，模型是 Qwen2.5-7B，不是生成模型的吞吐。
  二者不可直接相除比较，见下方 C2。

## 边界

- 模型加载未单独计时（本轮缺口）；预处理只含 `build_case`。
- 主表三次测量在同一 GPU 上，但 GPU 由多人共享；已用中位与范围报告，且 B/D 交替执行以抵消顺序偏差。
- 本轮不实现多分支 packing，也不更换推理引擎；D 的收益来自前缀复用本身。
