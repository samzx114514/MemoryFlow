# 可直接制作的逐页内容

建议 22 个主讲单元、5 个备选单元，约 34—38 分钟。编号用于内容组织，可以合并或拆分。正文围绕研究价值与机制，备选容纳公式和更多结果。证据 ID 见 03，案例全文见 04，视觉素材见 05。

## 01 封面：MemoryFlow

副标题：面向 Agent 多步任务的细粒度信息流溯源。角标：初期研究进展 / 2026 年 11 月。汇报人、单位使用占位，不编造。

图示：一条材料经过两步加工成为判断的简洁线索。讲述约 30 秒：我们希望回查一句重要输出的依据及中间加工过程。

## 02 Agent 的判断和引用需要能回查

页内文字：DCC 的判断需要具体规则与事实；报告中的结论和数字需要可核对出处；审阅者还会追问材料在中间被怎样解释。

证据：左侧用 NBA 最终结论短句，右侧用报告数字改写示意（E05/E08）。下方放“依据在哪里？中间变了什么？”两项实际问题。报告示意写明非本轮实测。

讲述约 1.5 分钟：答案看上去完整还不足以让人核查；我们关注能落到文字和运行记录的依据。转到已有来源研究的基础。

## 03 多步 Agent 扩大了来源分析的对象

页内文字：已有工作能分析一次回答与材料的局部关系；Agent 将原文加工为解释、摘要或记忆，再交给另一调用；最后一步不一定继续看见原始材料；执行模型与分析器可能具有不同接口条件。

图示：单调用与多调用两条结构，圈出摘要、传递和上下文变化。明确“局部来源信号承接艺峰工作”。不写已有方法在 Agent 上必然失效。

讲述约 1.5 分钟：问题从找一个出处扩展到追踪多个步骤，效果下降与适配限制要分别验证。

## 04 科学问题：跨步骤、可核查的来源链

中心句：如何在复杂 Agent 系统中，以可接受的额外开销，构建跨步骤、可核查的来源链？

解释三点：定位原始材料；保留中间加工；说明哪些有记录、哪些为模型估计、哪里追不到。Harness 是安排模型、工具与记忆协作的执行框架。

图示：一个最终判断与展开的材料层次。讲述约 1 分钟：以能核查的对象解释“可信”，不承诺自动判断真伪。

## 05 观察实际 DCC 流程：材料经过摘要进入报告

直接展示 E04 的三个文本框：合同 2.1 原句；研究者摘要中功能类比与复核提醒；报告返回的条款原句。保留原文高亮对应。

框下放两条事实：研究者看见 13 个合同片段；报告者看见摘要与其中 1 个片段。来源标“旧 CUAD 真实机制案例”。

讲述约 2 分钟：从真实流程观察信息流。目标条款也直达最终调用，所以此例解释多种路径并存，不证明多跳必要或报告犯错。

## 06 三类问题具有共同的内容传递结构

三行短例：规则/事实经解释形成 DCC 判断；文档数字经摘要变为报告引用；中间内容发生变化后被继续沿用的追查设想。

每行包含一条具体内容和一个核查问题（见 04）。报告/错误追查标为应用说明，DCC 标真实记录；不声称三个场景均已实测。

讲述约 1 分钟：用共同结构说明对象的扩展性。转到构建这种流的两项挑战。

## 07 两项挑战：每一步怎么算，各步怎样接

两栏：C1 高效局部关系——证据多、输出长、调用累积；C2 复杂 Harness 连接——压缩、子 Agent、分支与版本。

每栏放一个具体困难图和对应问题。下方标方法一/方法二的对应关系。

讲述约 1.5 分钟：保留会议认可的挑战划分；不把分数解释性替换成另一项科学挑战。

## 08 MemoryFlow 总览

页内文字：保存每次调用的输入与输出；独立分析器为局部内容建立来源矩阵；结合实际传递与会话历史，从最终内容反向查询。

图示：上层 Agent 真实流程，中层调用旁挂小矩阵，下层高亮一条回查路径（E07，示意）。显式承接艺峰与 Harness-RL。

讲述约 1.5 分钟：先讲最终能查到什么，再拆方法。无需介绍 RL。

## 09 方法一：对已知输出进行局部来源回放

页内文字：输出已经产生；保留该次输入和目标之前的真实输出；用独立分析模型读取细粒度关联；一行目标与多个候选来源形成可查询矩阵。

图示：输入片段→已知目标→热力图。可用 E04 的整段摘要—13 片段分数作真实小矩阵；示意 token 图不填伪造数值。

讲述约 2 分钟：TITO 是 Token-In/Token-Out。分数是分析模型给出的关联估计，不能称原执行模型依赖概率。

## 10 方法一：复用相同前缀减少重复计算

对照图：每个目标重算同一前缀；同一 tokenized 前缀只算一次，各目标依次分析。明确已实现部分为共享前缀、串行分支。

页内文字：只有输入 token、位置与可见范围一致才复用。已知目标按块分析与前缀复用分开解释。packing 作为“多分支隔离计算探索”用虚线标识，未有有效收益。

讲述约 1.5 分钟：这里解释机制，整批数字放实验页，不堆 mask 或缓存 API 细节。

## 11 方法二：用会话森林组织调用历史

页内文字：同一会话延续共同历史，分歧处可形成分支；主 Agent 和子 Agent 各有独立上下文；多个会话树组成森林。

图示必须是真正的节点/枝杈，按 05 的 F1 分步展开，标“概念示意，参考 Harness-RL §3.3”。主/子之间的委派或内容返回另画，不强拼成一根序列。

讲述约 2 分钟：先解释为什么有树、为什么有森林。真实运行的缺失标识不妨碍用示意解释方法，但不能把示意冒充已恢复轨迹。

## 12 方法二：把局部矩阵接到实际内容传递上

页内文字：森林记录谁能看见什么；矩阵估计输入片段与输出片段的关联；生成内容进入后续请求或文件版本时，沿确定传递继续追查。

图示 F2：先高亮一个调用并放大矩阵，再跨到子 Agent 摘要返回，最后从最终句反向高亮路径。记录确认用实线，关联估计用虚线，缺口用断点。

讲述约 2 分钟：输入出现与生成身份分开；不把会话树或内容相似当成已证实因果关系。完整根来源排序的组合规则尚未正式定稿。

## 22 回到研究价值

收束三点：Agent 的依据会跨步骤被加工；MemoryFlow 用局部关系与实际传递组织可核查来源；已有局部实证与工程原型，正在补齐系统级验证。

结束讨论聚焦：跨步核查应优先支持哪些真实需求、下一阶段如何评价路径的实际用途。不要以“全部完成”或复杂代码清单结束。

讲述约 1 分钟。
