# 表达与历史参考使用指南

## 本次汇报的风格目标

让老师看懂问题和证据。背景要让人感到这个问题值得研究，方法要让人看懂局部关系怎样接成流；正文避免陷入 token、mask、缓存和失败调试。

师兄给出的设计倾向是“证据明确、具体、干净”。落实到页面：结论旁边放真实短句、图表或前后对照；用足够内容解释这件证据；减少没有对象的抽象方框。信息密度来自实物和逻辑，不靠堆小字。

它们应启发：先展示输入输出与任务现象；实验页有对象、设置与可读数据；case 页把证据与解释并排；每页能够用一句话回答为什么放在这里。无需复刻原稿的方法观点、具体内容或所有排版。

## 推荐版式

- 背景：左右两个具体任务/输出，底部一条研究问题。
- 场景观察：原文、摘要、最终句三列，颜色对应短语；下一层显示可见范围。
- 挑战：两个并列问题，每个配实际结构，不做四五个泛化口号卡片。
- 方法：一张大图占主体，旁边两三句解释；森林与小矩阵通过放大局部联系。
- 实验：表或图成为主体，设置脚注短而清楚；不要把所有指标等权铺开。
- case：真实短引文和路径突出，完整调用 ID 放备注；待补状态靠近对应关系。

建议 16:9，浅底、深蓝主文字、青色强调，估计关系用橙色；中文用易读无衬线字体。字号按实际版面验证，主讲正文通常不小于 20pt。不要全稿只使用一种卡片布局，也不要为装饰牺牲证据可读性。

## 讲稿原则

先说这一轮做了什么和得到什么，再讲分析与建议。每页讲稿解释图中的具体对象及其与下一页的关系，避免把屏幕文字再读一遍。实验限制讲到影响结论的程度即可，不在每页堆同一段免责声明。

不要说“我们完全通用”“恢复了真实依赖”“证明前人不行”。可以说我们从局部来源走向跨步骤核查，目前哪些已有证据、下一步怎样验证。首次汇报应诚实呈现研究进展，同时充分说明价值。
