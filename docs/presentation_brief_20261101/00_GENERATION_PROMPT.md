# 可直接交给生成模型的任务

请基于此目录，为 MemoryFlow 生成一版完整、可编辑的中文研究进展 PPT，供团队后续制作正式稿参考。

这是第一次向老师汇报，听众还不熟悉项目，主讲约半小时以上。目标是让老师看懂研究问题、方法思路与已有进展，并认可研究价值。重点打磨背景、动机与方法的直观解释，具体实现细节进入备选页。

请先读 README、01—06 文档，再看 07 的视觉参考与本目录素材。内容与最新数字以证据账本为准；历史 PPT 仅作素材和设计参考。整个目录可离线阅读，不能访问私有仓库链接也不影响写稿。

## 故事线

组内可信引用需求；已有来源研究在多步 Agent 中需要扩展的对象；科学问题；观察真实 DCC pipeline 后引出信息流；三个场景的共同结构；两项挑战；方法总览；高效局部回放；复杂 Harness 的跨调用连接；来源质量、效率与正式 DCCv2 案例；进展与下一步。

基本遵循该顺序。02 提供 22 个主讲单元、5 个备选单元，可因内容合并或拆分；不要机械复制旧页码，也不要通过新增空页扩大规模。

## 内容与设计要求

- 直接产出完整参考稿，不停在提纲。正文使用 02 的具体内容、04 的原句和核准数据，必要时自行精炼文字与改进表达。
- 每页有一条清楚的主张、一件可读的证据或图示，以及足够理解它的解释。不要只留概念卡片或空流程框。
- 方法二是重点难点。借鉴 Harness-RL 的会话树/森林思路，分步画“各会话历史”“每个调用的局部矩阵”“跨步骤内容追查”。明确概念示意与真实案例，不能凭空为真实运行增加分支。
- 保留对艺峰来源信号、Harness-RL 会话组织的承接说明。无需介绍 RL 训练，也不把 Agent 整体画成可微大模型。
- 原文、摘要、判断用颜色或高亮对应。图表注明分母、单位、范围；正文足够大。优先简洁研究汇报风格，不必复制旧模板。
- 待补页照常做成完整布局，写明“待补证/待验证”，填入真实的任务背景、已有材料、比较对象和需要回答的问题，不编造结果或任意填数。具体处理见 06。
- 所有图和表可编辑，主讲与备选清楚分开。页内只保留必要短出处，详尽来源放讲稿或附录。

## 事实约束

- 正式 DCC case 使用 DCCv2；旧 CUAD 只作已有机制材料。SP1 不作为当前路线。
- 33/47 是局部来源前十找齐必要依据，不能写成答案正确率。
- 2.89 倍是同一回放方法内部的前缀复用收益，不能说比艺峰快 2.89 倍。
- 正式 NBA 单题运行完成但答错：预测 True/A/B，标准 True/B/B；这是 0/1，不是 216 题成绩。
- 新长文本读出百分比待校准，在线 E2 无结果，packing 未通过正确性；不把这些写成已验证优势。
- 来源分数是分析模型的关联估计，不是执行模型真实依赖概率或因果责任。不能凭关键词未命中就判“无依据”或“幻觉”。
