# 研究主线与讲述范围

## 希望老师带走的认识

Agent 已经能完成复杂任务，我们还需要知道每一条重要判断从什么材料而来、经过怎样的加工，以及哪里仍无法追查。这个需求来自组内 DCC 判断与报告引用场景。

艺峰的已有工作为局部来源分析提供了基础。进入多步 Agent 后，证据会被提取、解释、压缩成摘要，再进入不同 Agent 的上下文；任务也可能混用不同执行模型。研究对象由一次输入输出关系扩展到整个流程中的内容传递。

MemoryFlow 的做法分两部分：对已产生的输入输出进行独立来源回放；按实际调用和内容传递组织跨步骤来源路径。前者已有质量与计算复用实验，后者正在真实 DCCv2 案例上补齐。

建议标题：**MemoryFlow：面向 Agent 多步任务的细粒度信息流溯源**。

科学问题：**如何在复杂 Agent 系统中，以可接受的额外开销，构建跨步骤、可核查的来源链？** 通用可信溯源是研究目标，目前证据覆盖局部评测与案例原型。

## 从例子引出对象

先展示一次实际 DCC 流程中的原文、研究者摘要和最终结果，再引出“信息像流一样传递”的观察。不要先讲注意力或矩阵，再要求老师接受抽象名词。

可用旧 CUAD 原句作机制开场：研究者看 13 个片段，报告者看摘要与其中 1 个片段。目标条款也直达报告者，所以该例用于说明多种路径并存，不证明多跳必须更好。正式案例另用新版 DCCv2 NBA 运行。

再用三个短链路说明对象的共同性：DCC 的规则/事实到判断；报告中的原始数字到摘要再到引用；内容变化被后续沿用的追查设想。后两者没有本轮实测结果，不称跨三个场景已完成验证。

## 两项挑战

| 挑战 | 为什么存在 | 方法对应 |
|---|---|---|
| C1：高效构建局部来源关系 | 输入证据多、输出长、调用多，逐段分析成本累积 | 已知输出按块回放，复用完全相同前缀 |
| C2：适配复杂 Harness 的跨调用连接 | 摘要压缩、上下文改写、子 Agent、分支和产物版本 | 用接口记录组织会话历史，将局部内容关联接到实际传递 |

Harness 可解释为“安排模型、工具与记忆协作的执行框架”。TITO 只需首次解释为 Token-In/Token-Out：模型输入和输出。

## 方法讲述的粒度

方法一讲清输入片段、目标内容、一张局部来源矩阵和共享前缀。已知输出仍遵守因果可见范围；独立分析器有内部信号，执行模型可通过保存的输入输出与分析器分离。

方法二讲清三件事：不同会话各有历史；同一历史可能分支/改写，组成树集合；每次调用的局部矩阵描述内容关联，实际传递把它们接起来。会话森林表达可见历史，内容引用可跨树汇合。节点是可观测上下文，不宣称恢复全部内部状态。

承接艺峰的来源信号，借鉴 Harness-RL §3.3 的接口记录和会话组织。不要讲 RL 优化、奖励或梯度，不照搬训练时的历史清理策略。

## 实验证据的三层

1. **局部来源质量：** 能否找齐一组必要证据？用冻结 GenMem 主表。
2. **效率：** 计算复用是否有效？已有整批实测；完整用户任务中多等多久仍待在线结果。
3. **正式案例：** 能否把具体最终判断接回中间内容和原文/断点？新版 DCCv2 已完整执行，局部读出与跨步展示仍收尾。

小模型是成本/质量取舍探索，packing 是尚未通过正确性的补充优化。二者不作为已完成核心创新的前提。

## 结论应达到的强度

可以说：局部回放已有可用来源信号与计算复用收益；真实任务记录与跨调用原型可支撑进一步来源核查；正在补齐正式链路和在线成本。

不能说：恢复了执行模型真实因果依赖；所有 Agent 通用；能够自动判幻觉或修正判断；整体溯源质量/端到端速度已经全面优于前人。

目标是说服老师认可研究问题和实质进展。第一次汇报无需展示所有代码、失败日志、指标或全部实现细节。

## F1：方法二森林，先让老师看懂结构

至少画主会话和子会话两棵树。主树：初始上下文 H0，调用后 H1，后续 H2；从 H1 增加另一后续 H2' 表示共享历史后的分歧。子树：独立输入 S0，经分析得到 S1。主/子关系另外画委派与摘要返回。

这幅是概念示意，不需要把真实 v6 的 14/3/2/1 恢复链数量塞进去。节点解释为可观测上下文；树组织可见历史，调用标在相应路径上。工具/文件操作并非都属于 LLM 调用，应另标必要的内容传递。

用逐层出现或三幅小图：连续历史；共享前缀后分歧；不同会话各有一棵树。这样解释为什么是树、为什么是森林，比角色名称方框有效。

## F2：在调用旁挂局部矩阵，再反向追查

从 F1 放大一个调用：输入片段 a/b/c，输出片段 x/y，矩阵每格表示局部关联。在概念图中不填实测数值。再用一条返回的摘要连接子会话与主会话，最后从最终句反向高亮到摘要和原文。

记录确认用蓝色实线，回放估计用橙色虚线，缺口用灰色断点。传递箭头方向与查询方向分别说明，不能混为一套没有图例的箭头。

避免把 Agent 画成嵌入向量网络；不画 RL reward、梯度或训练损失。概念图只解释我们要构建和查询什么。

## F3：正式案例版面

四列或两层：原始任务/规则，关键解释，中间摘要/前版报告，最终判断。用真实短原句与颜色对应；旁边小字标生成调用/版本，详细 ID 进入讲稿。

当前只有经过记录确认的关系画实线，尚未核准的局部分数与上游映射写待补。页面仍应包含具体内容与核查问题，不留一个空的“case study”框。

原文同时直达最终调用时保留该路径；没有支撑段落时保留断点，不为好看补一条关系。

## F4：方法一与数据图

前缀复用图使用同色长前缀与不同目标块；优化后只保留一份前缀，组内目标依次分析。不要把现有 D 画成多个分支一次前向。

packing 另用虚线框写“探索中”，其 mask 图可说明分支应彼此隔离，但不能在结果栏放失败探针的速度。

质量图主表与柱图不必全部重复：一处突出完整组 @10，另一处保留 @5/Frag@1 的取舍。N=47 放在图中，不写 accuracy。

## F5：真实任务时间线

E0 是执行任务；E1 在同一保存轨迹后追加分析；E2 是真实执行与分析重叠。三条行中分别标答案时刻、来源齐备时刻、待处理积压和 GPU 配置。

没有 E2 数据时，条形长度必须标“结构示意，非比例”；时间字段写待测。完整任务额外等待应由实际两个事件计算，不能用局部 forward 时间外推。

## 两项核心证据收尾

| P02 | E1/E2 任务级成本：只有局部探针，无真实在线对照 | 画同任务 E0/E1/E2 对照设计；E0 571.9 秒已知，其他字段写待测；明确覆盖范围需一致 | 替换来源齐备时间、额外等待、GPU 与覆盖，不只替换一个速度数字 |

**这两项不阻塞生成完整参考稿。** 它们是内容应保留的位置，不能用随机数字或没有证据的结论填满。其余已核准页面照常精细制作。

## 补充与未开展项

- P03：packing 已有布局及真实模型探针，正确性未过，无有效加速结果；方法图用“优化探索”标识，结果留备选或下一步。
- P04：正式森林缺原生 session/delegate 的完整映射；概念图可画森林，真实运行只画有记录的链/传递，未知处保留缺口。
- P05：报告引用与错误追查的独立实证暂缓（原 G6）；只作需求/应用示意。新增基线训练后版本与方法名映射暂缓（原 G5）。

## 新回放数字为什么暂缓使用

新实现解决了长文本运行障碍，但本次审阅发现：目标行重建需要补实际因果屏蔽；两版候选不同，类别统计不能直接证明读出等价；user 消息中的摘要/控制信息被混标为 task_facts。具体 79.7%、51%/28%/20% 等占比不进入本版正文或数据图。

0.710 秒只计两条目标的 forward；原始记录还有评分时间，不能写“两句完整分析不到一秒”，更不能写成全任务成本。校准属于新读出的局部检查，旧 GenMem 主表和 2.89 倍结果不因此失效。

## 更新纪律

1. 先更新证据账本的状态、数据 CSV 与出处，再更新页面和图。保存旧版本，不默改分母或实验身份。
2. 未实际运行的比较保持“待测”；单次计时不改成多次中位。正常完成、交付存在、任务正确分别记录。
3. 案例可以答错；不能反复调整到答对再称首次成功。来源追查不能自动证明唯一错误原因。
4. 不依历史 PPT 的页码派任务。新版本主要打磨背景与方法表达，数据回传后原位替换。

# 表达与历史参考使用指南

## 本次汇报的风格目标

让老师看懂问题和证据。背景要让人感到这个问题值得研究，方法要让人看懂局部关系怎样接成流；正文避免陷入 token、mask、缓存和失败调试。

师兄给出的设计倾向是“证据明确、具体、干净”。落实到页面：结论旁边放真实短句、图表或前后对照；用足够内容解释这件证据；减少没有对象的抽象方框。信息密度来自实物和逻辑，不靠堆小字。

## 历史参考文件

|---|---|---|
| [v2 PPTX](references/MemoryFlow_v2.pptx) / [PDF](references/MemoryFlow_v2.pdf) / [文字](references/MemoryFlow_v2_text.md) | 方法叙述较凝练，输入、输出、局部矩阵解释可取材 | 故事线和状态较旧，数字不作最终依据 |
| [v3 历史 PDF](references/MemoryFlow_v3_history.pdf) | 背景与动机展开较充分 | 不机械保留页数和长方法解释 |

两份师兄参考稿为《SP周三组会-0422-多轮对话》《SP周三组会-0616-报告生成进展》。完整第三方 PPT 未复制进资料包；其身份与页数见 [索引](references/collaborator_reference_index.json)，本文件提供可独立使用的设计总结。

它们应启发：先展示输入输出与任务现象；实验页有对象、设置与可读数据；case 页把证据与解释并排；每页能够用一句话回答为什么放在这里。无需复刻原稿的方法观点、具体内容或所有排版。

## 推荐版式

- 背景：左右两个具体任务/输出，底部一条研究问题。
- 场景观察：原文、摘要、最终句三列，颜色对应短语；下一层显示可见范围。
- 挑战：两个并列问题，每个配实际结构，不做四五个泛化口号卡片。
- 方法：一张大图占主体，旁边两三句解释；森林与小矩阵通过放大局部联系。
- 实验：表或图成为主体，设置脚注短而清楚；不要把所有指标等权铺开。
- case：真实短引文和路径突出，完整调用 ID 放备注；待补状态靠近对应关系。

建议 16:9，浅底、深蓝主文字、青色强调，估计关系用橙色；中文用易读无衬线字体。字号按实际版面验证，主讲正文通常不小于 20pt。不要全稿只使用一种卡片布局，也不要为装饰牺牲证据可读性。

## 讲稿原则

先说这一轮做了什么和得到什么，再讲分析与建议。每页讲稿解释图中的具体对象及其与下一页的关系，避免把屏幕文字再读一遍。实验限制讲到影响结论的程度即可，不在每页堆同一段免责声明。

不要说“我们完全通用”“恢复了真实依赖”“证明前人不行”。可以说我们从局部来源走向跨步骤核查，目前哪些已有证据、下一步怎样验证。首次汇报应诚实呈现研究进展，同时充分说明价值。
