# 研究主线与讲述范围

## 希望老师带走的认识

Agent 已经能完成复杂任务，我们还需要知道每一条重要判断从什么材料而来、经过怎样的加工，以及哪里仍无法追查。这个需求来自组内 DCC 判断与报告引用场景。

艺峰的已有工作为局部来源分析提供了基础。进入多步 Agent 后，证据会被提取、解释、压缩成摘要，再进入不同 Agent 的上下文；任务也可能混用不同执行模型。研究对象由一次输入输出关系扩展到整个流程中的内容传递。

MemoryFlow 的做法分两部分：对已产生的输入输出进行独立来源回放；按实际调用和内容传递组织跨步骤来源路径。前者已有质量与计算复用实验，后者正在真实 DCCv2 案例上补齐。

建议标题：**MemoryFlow：面向 Agent 多步任务的细粒度信息流溯源**。

科学问题：**如何在复杂 Agent 系统中，以可接受的额外开销，构建跨步骤、可核查的来源链？** 通用可信溯源是研究目标，目前证据覆盖局部评测与案例原型。

## 从例子引出对象

先展示一次实际 DCC 流程中的原文、研究者摘要和最终结果，再引出“信息像流一样传递”的观察。不要先讲注意力或矩阵，再要求老师接受抽象名词。

可用旧 CUAD 原句作机制开场：研究者看 13 个片段，报告者看摘要与其中 1 个片段。目标条款也直达报告者，所以该例用于说明多种路径并存，不证明多跳必须更好。正式案例另用新版 DCCv2 NBA 运行。

再用三个短链路说明对象的共同性：DCC 的规则/事实到判断；报告中的原始数字到摘要再到引用；内容变化被后续沿用的追查设想。后两者没有本轮实测结果，不称跨三个场景已完成验证。

## 两项挑战

| 挑战 | 为什么存在 | 方法对应 |
|---|---|---|
| C1：高效构建局部来源关系 | 输入证据多、输出长、调用多，逐段分析成本累积 | 已知输出按块回放，复用完全相同前缀 |
| C2：适配复杂 Harness 的跨调用连接 | 摘要压缩、上下文改写、子 Agent、分支和产物版本 | 用接口记录组织会话历史，将局部内容关联接到实际传递 |

Harness 可解释为“安排模型、工具与记忆协作的执行框架”。TITO 只需首次解释为 Token-In/Token-Out：模型输入和输出。

## 方法讲述的粒度

方法一讲清输入片段、目标内容、一张局部来源矩阵和共享前缀。已知输出仍遵守因果可见范围；独立分析器有内部信号，执行模型可通过保存的输入输出与分析器分离。

方法二讲清三件事：不同会话各有历史；同一历史可能分支/改写，组成树集合；每次调用的局部矩阵描述内容关联，实际传递把它们接起来。会话森林表达可见历史，内容引用可跨树汇合。节点是可观测上下文，不宣称恢复全部内部状态。

承接艺峰的来源信号，借鉴 Harness-RL §3.3 的接口记录和会话组织。不要讲 RL 优化、奖励或梯度，不照搬训练时的历史清理策略。

## 实验证据的三层

1. **局部来源质量：** 能否找齐一组必要证据？用冻结 GenMem 主表。
2. **效率：** 计算复用是否有效？已有整批实测；完整用户任务中多等多久仍待在线结果。
3. **正式案例：** 能否把具体最终判断接回中间内容和原文/断点？新版 DCCv2 已完整执行，局部读出与跨步展示仍收尾。

小模型是成本/质量取舍探索，packing 是尚未通过正确性的补充优化。二者不作为已完成核心创新的前提。

## 结论应达到的强度

可以说：局部回放已有可用来源信号与计算复用收益；真实任务记录与跨调用原型可支撑进一步来源核查；正在补齐正式链路和在线成本。

不能说：恢复了执行模型真实因果依赖；所有 Agent 通用；能够自动判幻觉或修正判断；整体溯源质量/端到端速度已经全面优于前人。
