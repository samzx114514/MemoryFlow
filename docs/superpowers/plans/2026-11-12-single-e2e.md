# Single-call End-to-end Efficiency Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 为实验一补齐六行独立路线的批量均摊端到端秒/目标和全过程峰值显存。

**Architecture:** 新建single_e2e_v1入口，复用原pipeline的生成采集、完整回放、归约和作者引用函数。每模型单GPU、单权重服务，两路线分开运行；艺峰生成时采集，MF正常生成不采集再回放。目标按冻结文本精确定位，差异和缺失保留并按共同可定位目标报告实际分母。

**Tech Stack:** Python asyncio、现有vLLM独立序列服务、NumPy、NVML进程采样。

## Constraints and settings

- 最新优先级为本补测；宽展开16题已有结果保留，暂停新增多轮验证。
- 复用30个DCC输入、各模型冻结目标50/58/49；max_tokens2048、temperature0、seed0。
- 模型/头/候选切分/引用规则不改，正常生成不以teacher forcing替代。
- 每模型两路线同一A800、同一权重进程、同缓存配置。生成并发2，回放合批2，服务总请求容量4；记录实际batch和重叠。
- 模型加载与两路线短预检/预热单列；正式两路线独立，各3次，交错顺序。
- 主墙钟从第一条生成请求开始到全部引用文件就绪；完整矩阵归约、传输、存表、定位和引用筛选均包含。
- NVML仅统计本服务进程树，排除同卡其他用户；共享权重仅一次，保存原始时间序列、同时总峰值与每卡峰值。
- 每次调用完整生成/建表仅一次，多个目标共用；MF回放独立序列合批、与后续生成和CPU归约流水线运行。
- 原始输出token两路线相互核对并和冻结输出核对；缺失目标明示，禁止套用旧分母。
- 输出新目录，原质量表、实验三、原92题和PPT不变。
