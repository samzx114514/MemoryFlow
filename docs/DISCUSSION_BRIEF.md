# MemoryFlow：供下一阶段研究讨论的独立简报

**整理日期：2026-10-14**  
**用途：** 可单独交给网页端 GPT 阅读和讨论。本文给出研究问题、实验结论、证据边界与待决问题；网页端若未获得本地仓库文件，不能自动访问代码或原始产物。

## 我们最初想解决什么

在多 Agent 报告生成中，Researcher 检索多篇材料并写成 Memory Summary，Reporter 再写最终报告。MemoryFlow 希望把最终某一段话追溯到具体上游文本片段（Chunk），而非只知道 Agent 之间发生了调用。例如，“甲方法比乙方法效果更好”这句话究竟由哪段检索材料支持？Reporter 这次运行是否真的看到了那段 Summary？若替换材料，结论会不会变？这分别涉及**语义支持**、**实际使用**和**因果影响**，不能用一个引用排序分数统称为“真实信息流”。

## 已做的方法与转折

最初的 **Anchor + Attention** 方法由程序在每个 Chunk 后插入共享可训练 Anchor，希望它概括该段内容，再读取 Target Anchor 对多个 Source Anchor 的 Attention 来排序。结构化 mask 使多个候选可一起做一次 packed 前向，工程上确实节省推理成本。但旧 c8 LongCite 协议中，最佳 7B Anchor 的 Dev MRR 为 **0.576958**、nDCG@5 为 **0.581699**、Edge AUPRC 为 **0.335071**。它有信号，却不能证明 Attention 权重就是可靠来源边。扩大模型没有解决瓶颈。

随后冻结 Qwen2.5-7B，把每段文字编码为全文平均向量 `F_mean`，只训练轻量关系评分器。**R-SYM** 用 Target/Source 向量的逐维乘积、绝对差和余弦相似度评分，是交换两者后不变的对称模型。旧 c8 的置乱和困难子集核查支持其利用了两段文字的真实配对信息，超过只记 Source 先验；它仍不能表达方向。旧 c8 的 Ranking MRR **0.849765** 与 Edge AUPRC **0.550182** 来自分别训练的 checkpoint。R-SYM 与更大的 MLP 在主要指标上统计持平，因此作为较简单的统一候选保留。

为减少旧协议的混杂因素，本机从固定修订版 LongCite-45k 构建了 **LC-Sent-15**：每个 Target 需要在同文档 15 个候选 Source 中找唯一正例；Train **854 Targets / 12,810 pairs**，Dev **228 / 3,420**，Reserve **218 / 3,270** 且封存。引用标签是 Silver；部分负例为短的排版碎片。15 选 1 的均匀随机 Hit@1 理论值是 **6.67%**。

| LC-Sent-15 Dev 方法 | Hit@1 | MRR | nDCG@5 |
|---|---:|---:|---:|
| BM25 关键词匹配 | 0.6842 | 0.7470 | 0.7433 |
| Qwen 全文向量余弦 | 0.451754 | 0.595358 | 0.619916 |
| R-SYM（三种子均值） | 0.754386 | 0.827306 | 0.843610 |
| D-Full-64（三种子均值） | 0.780702 | 0.851374 | 0.869965 |
| 固定 Fusion | **0.831871** | **0.885701** | **0.897075** |

Hit@1 看第一名是否正确；MRR 也奖励正确来源排在第二、第三；nDCG@5 看前五名的排序。**D-Full-64** 在输入中分别保留 Target 和 Source 向量，具备角色感知能力，但其相对 R-SYM 的增益区间跨零，Train–Dev 差距更大，不能据此断言学会真实方向。**固定 Fusion** 用 Train 五折折外预测先选定 0.65 的 D-Full 权重与 0.35 的 BM25 权重，再看 Dev；它显著提升 Dev，但更像有效系统组合，不是独立创新点。旧 Anchor 数字属 c8，不能与本表当作同协议直接横比。

## 向真实报告链路迈进到哪一步

**Synthetic Summary Track A** 有 137 个单文档生成 Target，BM25 Hit@1 已达 **0.9416**，任务词面重合过强，只是乐观 smoke test。**Track B** 有 10 个多文档 Summary、143 个 clause、4,194 个 Source sentence；没有 Gold 或 Judge 结果，方法一致率不能写成准确率。继续优化这两个合成 Track 对核心问题帮助有限。

本机旧 SP 日志可以导出工作流和段落，但 20 个 pilot Case 没有可直接恢复的 Source→Report 语义 Gold 边。后续选定 SP1.0 生成自然轨迹，期望记录检索 Source、Researcher Summary、Reporter 输出及稳定 ID。按本轮找到的资料，**尚无完整可评价的真实 SP1 轨迹或 Source-to-Summary 指标**。这是下一步能否讨论真实信息流的最大证据缺口。

合作者的艺峰方法在生成时聚合 Attention 做引用归因。243 的 Head-probe readiness 报告标记所需输入不齐，未见计划的 100 中文 + 100 英文样本 probe 结果；LC-Sent-15 对比报告指出“给定已存在 Target”如何公平评分仍有协议歧义，因此没有可并列表述的艺峰方法 Dev 分数。

## 已有结论与边界

1. Packed Anchor + Attention 工程可行，但 Attention 读出不足以充当可靠来源边。
2. 冻结 Qwen 表示中的关系信息需要专门评分器才能有效使用；R-SYM 的旧 c8 机制实验支持真正的 Target–Source 语义匹配，而非纯 Source 先验。
3. LC-Sent-15 上非线性关系评分和固定词法融合显著有用；它们仍是引用代理任务证据。
4. 目前没有证据证明方法恢复了真实 Agent 的实际使用、方向性或因果影响；也没有可用的艺峰方法同协议成绩。

## 建议与 GPT 讨论的问题

- 如果论文主张是“信息流”，最小可信的真实轨迹标签应是什么：显式引用、输入可见性、人工语义支持，还是干预后的变化？各层怎样分开评估？
- 是否应先冻结一个 SP1 查询的 Source/Researcher Summary/Reporter trace schema，只对有稳定 ID 的可证边计分，再决定是否扩到十个查询？
- 面对真实 Summary 改写和多源融合，BM25、R-SYM、D-Full 与 Fusion 的相对优势可能如何变化？哪些错误例子最能区分方法？
- 方向性是否值得做主贡献？需要什么角色交换、时间约束或反事实实验，才比 c15 的 D-Full 点估计更有说服力？
- LC-Sent-15 是继续作为主基准，还是作为方法回归测试？如何处理 Silver 标签和排版碎片负例？
- 艺峰生成时 Attention 方法与给定 Target 的后验评分，能否定义共同任务？若不能，是否应作为不同问题分别评价？
