建议用时：0.5 分钟。

我们关注的是 Agent 任务完成之后，人怎样核对一句重要输出的依据。MemoryFlow 希望让审阅者看到原始材料、途中产生的解释，以及最后采用的判断。本次汇报按研究问题、两部分方法、已有实证和仍需补齐的系统验证展开。

资料依据：01_NARRATIVE_AND_SCOPE.md。文件路径相对于 `docs/presentation_brief_20261101/`。

### 02 Agent 的判断，需要能回到依据

建议用时：1.5 分钟。

从组内需求看，DCC 要给出合规判断，报告生成要引用事实和数字。这里左侧是正式 NBA 运行的真实输出，右侧是会议中的报告场景。它们表面不同，但审阅者都会问：依据在哪，处理中有没有增加解释或者改变条件？我们关心的是把核查落到具体文字。先不展开 NBA 哪条规则正确，后面的案例会回到这个问题。

### 03 多步 Agent 扩大了来源分析的对象

建议用时：1.5 分钟。

已有来源研究为一次回答和其输入之间的关联提供了基础，我们承接艺峰的局部来源信号。进入 Agent 系统后，同一份原文可能先被研究者解释，再压缩成摘要，最后交给报告者。最后一步看到的材料和第一步不同。我们扩展的是分析对象和接口条件，不预先假设已有方法一定失效。

### 04 跨步骤、可核查的来源链

建议用时：1 分钟。

我们提出的科学问题是，如何在复杂 Agent 系统中，以可以接受的额外成本建立跨步骤且可核查的来源链。可核查有具体含义：能定位材料，能看到中间加工，也能知道哪部分来自记录、哪部分来自模型估计，哪里暂时查不到。Harness 就是安排模型、工具和记忆协作的执行框架。我们还没有把来源关联等同于真实性或因果影响。

资料依据：01_NARRATIVE_AND_SCOPE.md。文件路径相对于 `docs/presentation_brief_20261101/`。

### 05 一条合同条款，在处理中增加了解释

### 07 两项挑战：每一步怎么算，各步怎样接

建议用时：1.5 分钟。

要把刚才的想法实现，有两类困难。第一类是计算量，调用多、材料长、需要分析的目标也多，逐目标重算会反复处理相同材料。第二类是连接结构，子 Agent 有自己的上下文，摘要会压缩，报告还有版本。如果把所有调用直接拼成一条序列，就丢失了谁实际看到什么。方法一负责有效率地产生局部关系，方法二负责按实际系统组织和连接它们。

资料依据：01_NARRATIVE_AND_SCOPE.md。文件路径相对于 `docs/presentation_brief_20261101/`。

### 08 MemoryFlow：局部关系与实际传递协同

建议用时：1.5 分钟。

先看整体。上面是正常运行的 Agent，它的调用输入和输出被保存。中间的独立分析器读这些已知内容，给出每次调用的局部来源关系。再按实际传递把前后的内容接起来，审阅者就可以从一个最终句向前查询。局部信号承接艺峰工作，会话组织借鉴 Harness-RL。接下来先讲局部矩阵怎样产生，再解释会话森林如何承载它们。

### 09 方法一：对已知输出进行局部来源回放

建议用时：2 分钟。

这里的输出已经生成，分析时保留实际输入和目标之前的真实输出，用冻结的独立分析模型读取来源关联。TITO 指 Token-In/Token-Out，也就是输入和输出。矩阵的行是目标，列是候选来源。右侧给的是旧合同例里整段摘要这一行的实际结果：十三个候选中，第 2.1 条所在片段排第一。这个分数属于分析器的关联估计，不能解释为执行模型使用它的概率。目标的粒度也不能偷换，整段摘要分数不等于其中某个句子的分数。

资料依据：03_EVIDENCE_LEDGER.md、data/cuad_summary_scores.csv。文件路径相对于 `docs/presentation_brief_20261101/`。

### 10 方法一：相同前缀只计算一次

建议用时：1.5 分钟。

同一次输入常有多个目标。逐目标分析时，最长的相同材料会重复计算。当前实现把完全相同的 token 前缀算一次并保存，目标分支仍然依次分析。这和把多个目标一次性打包不是同一件事，后者还在正确性验证中。复用的前提是 token、位置和可见范围一致。我们希望保持每个候选分数不变，减少的是重复计算，后面实验会给出实际收益。

资料依据：03_EVIDENCE_LEDGER.md、evidence/prefix_reuse.md。文件路径相对于 `docs/presentation_brief_20261101/`。

### 11 方法二：会话历史组成一片森林

建议用时：2 分钟。

先不看分数，只看谁能看见什么。左侧一个会话从 H0 延续到 H1，如果共享历史之后发生不同后续，就会形成分支。右侧子 Agent 有自己的输入 S0 和后续 S1，因此是另一棵树。主会话委派任务、子会话返回摘要，是两棵树之间的内容交互，不能把独立上下文当成同一条历史。这里借鉴 Harness-RL 的会话组织。节点表示可观测上下文，不声称恢复模型全部内部状态。这是方法概念图，图中的备选分支不是正式 NBA 运行里已经观察到的分支。

资料依据：05_VISUAL_BRIEFS.md。文件路径相对于 `docs/presentation_brief_20261101/`。

### 12 方法二：局部关联接上实际内容传递

建议用时：2 分钟。

有了森林之后，我们再把内容关系放进去。子调用从可见原文产生摘要，局部矩阵估计输入与输出的关系。摘要实际进入报告者请求，这一步由记录确认。报告者又产生最终句，另一个局部矩阵描述该句与可见输入的关联。用户从最终句反向查，就能逐段走向中间内容与原文。这里实线和虚线含义必须区分，文本相似不能代替生成归属，输入出现也不等于被使用。如果上游记录或映射缺失，就在这里停下来。完整的根来源排序组合规则尚未正式定稿。

### 25 短条件下，独立回放仍有额外成本

备选页，按需展开。

这页是短路线对照，回答独立分析是否天然更快。正常生成 S 的中位时间为三点六八七秒，生成时捕获增加到四点零九七秒，生成后再串行回放合计四点七零一秒。这个条件下串行回放稍慢。两条分析路线并非同骨干，生成使用二十七 B FP8，回放使用七 B，模型也没有共驻；重复次数不同，回放只有一次。因此只能报告这一条件的现象，不能外推整体在线速度或同骨干算法优劣。
